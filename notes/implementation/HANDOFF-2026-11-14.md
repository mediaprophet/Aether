## 2. Architecture that must be preserved

QualiaDB is the required application foundation. Use its canonical `crates/vibe`
engine and `crates/vibescript-abi` provider, lifecycle, memory and SDK contracts.
The sibling `vibe-script` repository is tooling, not a replacement language engine.
The generic Chora engine must not acquire QualiaDB/Webizen-specific dependencies;
host authority and ecosystem integration belong in Aether/Webizen.

Native Blitz/AnyRender and Chora have incompatible in-process Stylo/ICU
requirements. The implemented composition therefore uses separate processes:

```text
Native application / canonical signed host authority
  -> ChoraGraphRoutes + optional client event pump
  -> ChoraClient (owned child, private stdin/stdout, drained stderr)
  -> bounded CHOR protocol
  -> aether-chora-worker (actual sibling Chora, engine-thread-owned handles)
  <- copied RGBA pixels
  -> ChoraFrameWidget / AnyRender
```

Only copied pixels cross this boundary. There is no shared GPU device/resource
claim. A separate process is **not** OS containment. The current worker admits
only explicit `TrustedEmbedding` and public browsing; required sandbox and private
browsing requests fail before engine startup. Chora retains traditional JavaScript
and WebGPU behavior through SpiderMonkey. V8/Node-specific APIs are separate,
unimplemented compatibility requirements unless explicitly demonstrated otherwise.

## 3. Implemented components and limits

| Component | Implemented behavior | Important limit |
| --- | --- | --- |
| `packages/chora-bridge-protocol` | Versioned framing; monotonic sequence and direction checks; full session/view/generation/document/viewport stamps; bounded codec and mailbox | Control messages 128 KiB; RGBA frames 16 MiB; stamps identify routing, not authority |
| `packages/chora-client` | Owns child and private pipes; random session nonce; environment whitelist; nonblocking UI operations; bounded queues; independent deadlines and reaping | Explicit absolute executable; public trusted profile only; diagnostic stderr is currently discarded |
| `packages/chora-worker` | Actual sibling `servo` package as Chora; engine/view/request handles remain on engine thread; real caller getters; readback and structured failures | No input forwarding, private profile, OS sandbox or general navigation/history implementation |
| Worker shutdown helpers | Protocol stdout isolation; bounded input queue; independent EOF/overload watchdog; Windows `TerminateProcess` / Unix `_exit` | Windows fixture execution only; no Unix runtime or Windows DLL-detach stress proof |
| `packages/qualia-host/src/chora.rs` | Explicit signed `NativeGraphBridge` route registration; bounded/cancellable snapshot requests; optional concrete-client event pump | Only `qualia.graph.snapshot` with exact `{}`; page claims and the session nonce confer no authority |
| `packages/native/src/chora_frame.rs` | Copied AnyRender image; full-stamp checks; one outstanding capture; final redraw clears terminal images | Alpha/orientation, real window pixels and input/accessibility remain unqualified |
| Source capture/profile scripts | Capture optional/aliased transport dependencies; deny escapes and unreviewed sources; explicit `--with-chora-client` host profile | Frozen native+captured-client composition is deliberately rejected until source ownership is coherent |
| `stage_runtime.py` | Selects actual executable and ANGLE producer from successful Cargo JSON; hashes exact copied artifacts; checks PE imports and destination ancestry; retains notices/receipts | Local development stage, not complete distribution or installed-runtime qualification |

The client and worker allow at most 64 outstanding page requests and eight
additional control/lifecycle queue slots. Requests and startup/navigation/resize/
capture operations have 30-second deadlines; shutdown grace is two seconds.
The client keeps one latest frame. Readback admission reserves a conservative
four-buffer budget, at most 64 MiB for the admitted 16 MiB frame. These are local
boundary limits, not a claim that all engine/GPU allocations are bounded.

Explicit parent navigation creates a fresh WebView/delegate, retiring old request
handles and callbacks and resetting history. Internal navigation within a view
still lacks a demonstrated exact document-to-paint commit identity. URL changes
alone must not be treated as proof that pixels belong to the new document.
